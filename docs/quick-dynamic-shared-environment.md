# 快速动态验证：共享环境与逐报告预算

本次改动落实到 P08 快速 Web 验证主链：一次共享环境准备最多 **240秒**，之后每个符合条件的疑似漏洞报告各有 **180秒**。预算由控制器计时，模型不能通过进度或重写文件续期。`N` 条报告的验证阶段总上限是 `240 + 180 × N` 秒，另有最多约5秒的本次 OpenCode 子进程退出宽限。例如5条报告最多19分钟，不含此前静态挖掘及后续静态复核。

## 共享内容与生命周期

一个 `run-quick-dynamic-validation.mjs` 启动一个 OpenCode 验证进程，该进程持续持有同一 Chrome DevTools MCP 会话。无需逐报告重复启动浏览器或重做环境准备。准备阶段检查用户提供的本机测试环境、完成必要登录并建立测试基线；不挖掘或验证具体漏洞。

当前快速代理没有 shell 权限，240秒准备是**已提供环境的就绪、登录和测试基线准备**，不是任意源码构建、服务安装或部署。Windows 客户端/Java 联合验证的受控启动与部署仍需按对应设计接入专门的环境准备器，不能宣称已经自动搭建完整产品。winappCli 仍是独立受控 PoC，本次没有把审计任务的 Web opt-in 扩展为桌面控制授权。

环境复用范围为同一 `audit_id + round`；不跨任务、轮次或恢复后新进程复用桌面/浏览器状态。攻击者、受害者、不同租户测试账号保持独立上下文。可以保留角色的登录基线，但不能将某报告的残留载荷或身份串给下一报告。每报告180秒包括验证、证据保存和清理；最后一条还需关闭本次创建的 pages/contexts。

## 调度与产物

1. 校验显式任务开关、intake、私密上下文摘要和 loopback URL。未开启、为空、无效或缺少必要账号时 SKIPPED，继续静态流程，不询问或访问目标。控制器在启动进程前检查摘要/URL；代理在第一次浏览器调用前检查账号与登录说明是否满足目标需要。
2. 控制器在 `reports/validation/control/<run-id>.json` 发布 SETUP 阶段及唯一 `phase_id`。240秒包含本次验证会话启动、模型响应、工具调用和准备结果交付。
3. 只有准备 READY 才逐条发放 FINDING 阶段；每次发布重新开始独立180秒计时。模型只处理当前 finding，提交完整结果后等待新阶段 ID，不得提前验证下一条。
4. 每个阶段写独立的 `reports/validation/quick/sessions/<run-id>/<phase-id>.json`，模型不写最终结果集。控制器验证字段、报告绑定和证据真实文件，真实耗时取控制器计时。
5. 控制器结束本次验证进程，复查各证据摘要，聚合封口到原有 quick result 路径。此前有效结果不会因后续单条失败而全部改为失败；证据被后续改写的那一条会被拒绝采信。

新版 intake 和 quick result 为 schema v2：`deadline_seconds=180` 表示每报告预算，`setup_deadline_seconds=240` 表示准备预算，`environment_reuse=AUDIT_ROUND`。结果新增 `environment_setup`；每条增加 `cleanup_status`。旧版 schema v1 的120秒制品仍可读取与校验，但不能再启动动态验证，需重新生成 intake。静态三方/routing 的 schema 保持 v1，绑定新版制品摘要。

## 超时和失败语义

| 情况 | 结果与后续动作 |
|---|---|
| 未授权或环境信息不满足门禁 | setup SKIPPED，报告 SKIPPED，继续静态复核 |
| 准备超时 | setup TIMED_OUT，报告 SKIPPED；报告预算尚未开始 |
| 准备实际失败 | setup BLOCKED，报告 SKIPPED |
| 单条超时 | 当前 TIMED_OUT、cleanup UNKNOWN；保留已接收结果，后续 SKIPPED |
| 单条干净结束但未确认 | NOT_CONFIRMED，继续下一条独立180秒 |
| 单条已确认但清理失败 | 保留有有效证据的 CONFIRMED，同时记录残留及清理失败；后续 SKIPPED |
| 输出无效/进程异常 | 当前 BLOCKED；停止环境复用，后续 SKIPPED |

超时意味着该会话的控制/清理状态不再可信，因此当前实现停止该会话，不自动重建环境接着测试。不会全局终止 Chrome；若任务自建页面未能关闭，记录 UNKNOWN 与需要人工恢复的范围。后续若要“单条超时后仍继续”，需增加可独立撤销的操作队列与受控环境恢复确认，不能简单重启浏览器绕过清理状态。

所有非 CONFIRMED 结果仍进入既有静态三方流程，完整动态验证继续由工作台手动触发。

## 验证范围

新增测试覆盖独立计时、准备超时、单条超时保留前序结果、共享进程、清理失败停止、非法阶段、远程目标、缺失/变更证据、无授权不启动，以及v1读取兼容。已加入 Windows/Linux CI 的 `test:truth-validation-contract`。本次编辑环境为 macOS，遵守项目支持主机约束，只做语法、配置及静态一致性检查；没有在本机运行平台测试或真实浏览器验证，Windows/Linux CI 和实际本机测试环境验证仍待执行。

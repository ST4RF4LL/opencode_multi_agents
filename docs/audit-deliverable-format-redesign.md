# 漏洞挖掘交付件内容与格式调整

分析日期：2026-09-18。首要目标：完整呈现审计证据与验证过程，让审阅者能够重建“检查了什么、观察到什么、如何排除反例、为什么得出结论”。修复建议作为后续处置部分保留。报告的有效信息量由证据和判断完整性决定，不以字数作为验收标准。

可直接审阅 [单项漏洞格式预览](examples/audit-evidence-report.example.md)。示例由实际渲染器生成，使用合成数据，不代表真实漏洞审计或动态验证。

## 当前信息损失

源码检查和现有最终报告样本 `audit-20260831-yh5ae` 表明：

1. Finding v2 有来源、危险操作、攻击面、反证、盲点，但修复只要求 `remediation.summary`，没有强制成因分解、可复核路径、复现设计和回归标准。
2. 裁决已有 `semantic_proof`、四层防护检查、反方主张；最终模型只提取裁决摘要，丢弃这些过程信息。
3. 三方复核已有逐项 claims、reasoning、证据和 gaps；最终模型只保留路由与最终标签，读者无法判断双方争议及裁定依据。
4. 运行证据保留 observations、proof、evidence_ids，最终报告主要显示状态和概述，且旧正文使用通用静态/quick 文案，不能准确表达贯穿式测试。
5. CVSS 原有评分理由与假设、攻击链原有步骤与连接，在报告模型中分别被缩减为分数/向量和链 ID/状态。
6. 样本还存在英文人工说明、相似标题与位置重复出现、排除项只有 ID/状态的问题。相似记录需要关联阶段证明是否同源，不能由渲染器按标题自动合并。

## 各环节交付职责

| 环节 | 必须交付的业务内容 | 下游如何使用 |
|---|---|---|
| Scope / Recon | 冻结版本和范围；组件/框架；入口、敏感操作、配置定位；识别方法；已知盲区 | Threat 和审计必须能回到代码定位；未知项保持缺口 |
| Threat / Focus 规划 | 威胁主体、资产、边界、攻击假设；Area 范围与责任分派；为什么需要审查；必需证据 | 生成可核对分派，不以风险关键词替代实际边界 |
| 专业审计 | 原始 Finding v2 + `report_details`；三视角事实；未覆盖/跳过 Area 与原因 | 每个漏洞包含成因、路径、代码上下文、复现设计和修复/回归方案 |
| 关联分析 | 原始 Finding ID、摘要、来源；同源判断理由；各视角证据、保护、矛盾及需追问事项 | 保留来源，不把冲突压成一条无依据结论，不凭相似标题合并 |
| 独立裁决 | 框架/API/版本语义；输入到效果的逐步路径；local/inherited/global/deployment 防护；最强反例及处置 | 区分候选主张与独立判断；不能只有“已证明” |
| 动态参与 | CONTACT 基线；EXPLORE 假设与观察；CONFIRM 绑定候选摘要；实际动作证据、结果、清理及限制 | 与静态复现设计分开；SKIPPED/NOT_TESTED 不冒充复现成功 |
| 正方/反方/裁定 | 各方主张、复核证据、完整理由、未解决问题、最终结论边界 | 最终报告逐项保留复核内容，而不是只保留 TRUE_POSITIVE |
| CVSS / 攻击链 | 向量及评分理由、假设、证据；有序步骤、连接条件、证据状态与阻断缺口 | 分值可解释，条件链不冒充已验证链 |
| 最终报告 | 从上述已验收内容确定性组装，并列出内容缺口、覆盖缺口、动态状态 | 不在最后一个 Agent 中凭摘要重新编写事实 |

## 单项漏洞最终结构

1. 标识、等级、主要代码位置、入口、认证要求、主体与边界。
2. 成因：应有行为、实际行为、缺失或错误的安全约束。
3. 证据链：E0/E1 等事实编号、文件与行号、取证方法、源码摘要、置信度、已提供的脱敏代码上下文。
4. 专业审计的事实路径、独立裁决的语义路径分别展开，以及关键框架/版本/API 语义及证据。
5. 利用前提、影响范围、部署假设和盲区。
6. 已检查的四层防护、反证、最强反方主张及处置依据。
7. 复现设计：环境要求、前提、步骤、安全/漏洞行为预期，明确未执行。
8. 实际运行记录：逐包状态、假设及候选绑定、观察、应用层证明、证据文件及摘要、输入/结果摘要、清理及残留。
9. 正方、反方、裁定方的主张、理由、实际复核证据、事实包与独立会话绑定、运行证据判断及最终裁定。
10. 修复位置、动作、原理、临时缓解、兼容性说明、安全与功能回归用例。
11. CVSS 评分理由、适用假设和证据。
12. 交付信息缺口和原始候选/裁决/运行/三方制品引用及摘要。

误报与证据不足的候选也保留处置依据，不计入真实漏洞数量。攻击链展开步骤、连接和缺口。Area 跳过清单保留上一轮的 SKIPPED 标识与原因。

运行测试附录保留 CONTACT、EXPLORE、CONFIRM 的完整已交付过程和证据索引，包含未映射到源码漏洞的测试与环境候选三方复核。单项漏洞只关联当前候选对象摘要及其关联假设的运行包，历史候选的确认结果不能自动归到更新后的候选上。

## 实现与兼容边界

- 新生成的 Coverage Plan 显式声明 `finding_detail_contract=finding-details.v1`，TODO 和工作包保留该标识；工作包提交校验拒绝内容缺失/无效的候选，沿用 watchdog 提醒链路。未知契约不能静默按旧版处理。
- Finding 仍为 v2，`report_details` 是受对象摘要保护的版本化扩展。旧任务未声明时保持原验收行为，已有摘要不重写。
- 事实包保留 `report_details`、定位和修复信息，三方在同一事实包内复核。
- 新构建的最终模型声明 `detail_contract=audit-report-details.v1`，增加逐漏洞 `dossier`：原始 Finding、独立裁决、角色复核、绑定运行包和来源引用。保留已有报告 schema 2/3 的真实性协议区分。
- 贯穿式运行附录保留已封存的完整 evidence set 与运行候选三方记录；收尾核对其摘要、角色会话、当前 Finding 绑定和原始运行制品。渲染不启动浏览器，也不重新执行测试。
- 新渲染器只读取已验证输入，不执行请求、不读取目标源码补写片段、不翻译历史事实。历史内容缺失或非中文标题进入 `delivery_gaps`；缺少代码片段时明确显示原因。未声明新报告内容契约的历史模型继续使用原渲染方式。
- 内容检查证明字段和引用结构满足要求，不能替代源码真实性核验。代码片段由上游提供，源码摘要绑定不等于片段已经被程序逐字核对。
- Scope/Recon、Threat 和关联阶段的现有机器协议未整体换版；本次明确其交付内容职责并加强下游保留，未将新的说明性要求声称为已存在的逐字段强制门禁。

## 验收场景

新工作包缺少成因、路径事实索引越界、复现计划伪装已执行、无安全/功能回归用例，应拒绝提交。已提供的原始事实、裁决路径、角色理由、动态观察、评分依据及攻击链步骤必须进入最终报告。没有环境时显示动态跳过，历史缺字段显示交付缺口；候选处置与 Area 跳过不能被隐藏。报告仍必须通过模型校验和确定性渲染校验。

本次自动回归覆盖：内容契约及信息保留、TODO/watchdog 交付门禁、最终模型构建与确定性渲染、运行证据绑定、旧版真实性协议兼容以及工作台回归。测试使用临时目录与合成证据，未执行真实目标动态验证；macOS 上使用既有便携测试开关，不代表 Windows/Linux 原生部署或真实多 Agent 审计已验证。

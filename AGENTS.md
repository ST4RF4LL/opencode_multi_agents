# Dynamic validation safety boundaries

- Reports and audit deliverables must be written in Chinese. Machine-readable artifacts (JSON, digests, code comments, identifiers) stay as-is; only human-facing narrative, findings, and report text use Chinese.
- Never reset browser state by killing Chrome or Chromium processes globally. Do not use `pkill`, `killall`, wildcard PID termination, `taskkill`, `Stop-Process`, or equivalent process-wide commands against Chrome. Close only pages or browser contexts created for the current validation through the configured browser controller. If that cannot recover the session, stop and report the blocked state.
- Run dynamic validation only when the user explicitly requests it and supplies an authorized test environment. The current dynamic-validation scope is limited to `localhost`, `127.0.0.1`, and `[::1]`. Never validate production, third-party, remote staging, container-internal hostnames, unrelated tenants, or real-user accounts.
- Do not start dynamic validation merely because a static finding or runtime-validation request exists. When dynamic validation was explicitly requested but environment, account, or login details are missing, only the primary orchestrator may pause and ask the user for them; subagents must return a blocked handoff.
- For XSS, CDP-driven DOM injection may be used only as a quick browser-control probe. It is not application vulnerability evidence. Prefer proving stored XSS submitted through a real application input, surviving refresh or revisit, and executing in a distinct authorized victim account and isolated browser context.
- Use unique, non-destructive proof markers. Do not read or exfiltrate credentials, tokens, personal data, or unrelated records. Never create backdoors, system persistence, or reusable weaponized payloads.
- Attempt to remove stored test payloads through the authorized application cleanup path. Cleanup failure does not erase an otherwise valid finding; record the still-present payload, affected test scope, failed cleanup evidence, and required manual remediation.
- Use Chrome DevTools MCP for the current implementation. Do not use or silently fall back to `agent-browser`.
